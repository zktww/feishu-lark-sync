# Security policy / 安全报告

## Supported versions

Security fixes are intended for the latest 1.0.x release. Versions 0.x are development builds; upgrade and retain a backup before migrating. A version number alone is not a security certification.

## Private reporting

Please do **not** disclose vulnerabilities, real document links, credentials, state files or private note contents in public Issues or PRs.

Once this repository is public and private vulnerability reporting has been enabled, use **GitHub → Security → Advisories → Report a vulnerability**. If that option is unavailable, open only a minimal request for a private contact channel, without vulnerability details or sensitive information. Do not assume a private reporting channel exists until it is configured.

Include affected versions, impact, reproduction with synthetic data, and a proposed mitigation if available. Maintainers will assess the report and coordinate a fix and disclosure; no response-time guarantee is currently offered. Do not probe other users' accounts or services without authorization.

如需报告漏洞，请使用仓库启用后的 GitHub 私密漏洞报告入口；入口不可用时，只发“需要私密联系渠道”的请求，不在公开 Issue 中贴漏洞细节、密钥、文档 URL 或状态文件。请使用脱敏或合成数据复现。

If credentials have already been exposed, revoke or rotate them through the relevant provider. Deleting a Git file or commit does not invalidate leaked credentials. See [privacy and data handling](PRIVACY.md) for storage boundaries and retention.
