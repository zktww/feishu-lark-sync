# Feishu Lark Sync

[English](README.md) | [简体中文](README.zh-CN.md)

`Feishu Lark Sync` 是一款桌面端 Obsidian 插件，用于将飞书或 Lark 中的文档同步到本地 Obsidian 知识库。

- 插件名称：Feishu Lark Sync
- 插件 ID：`feishu-lark-sync`
- 数据方向：飞书/Lark → Obsidian
- 数据原则：本地优先、用户授权、无第三方中转服务

## 当前状态

版本 1.0.1 提供 doc/docx 拉取链路、同步中心、分步配置、冲突处理、状态恢复和经过校验的发布打包：

- Obsidian 插件工程和设置界面
- 独立的 `lark-cli` Profile 配置
- App Secret 仅通过标准输入传递给 `lark-cli`，插件不会持久化保存
- 通过浏览器授权链接完成用户身份授权
- 检查飞书/Lark 用户登录状态
- 支持配置多个同步源
- 以用户身份递归、只读地扫描 Wiki 节点和云盘文件夹
- 手动处理云盘分页，并保护重复资源和目录循环
- 将 Docx/旧版 Doc 正文转换为本地 Markdown
- 将飞书图片和文档附件下载到相邻的 `_attachments` 目录
- 根据 revision/修改时间执行增量同步
- 只更新托管正文区域，保留本地 Frontmatter 和笔记
- 检测托管区域的本地修改并阻止静默覆盖
- 支持 Obsidian 启动时同步和 15/30/60 分钟定时同步
- 支持单篇文档 URL 同步源

Sheet、Base、Slides 和思维笔记目前只会被发现，尚不转换正文；普通云盘文件不导入。画板保留占位提示。远端文档消失时不会删除本地笔记。

## 同步方式与本地编辑

- 点击侧边栏图标或执行“打开同步中心”命令，查看进度、手动同步、取消任务、仅重试失败项。也可以开启“启动时同步”和定时间隔。
- 文档写入同步源配置的知识库目标目录，并保留远端文件夹层级。
- 飞书正文位于 `<!-- feishu-sync:start -->` 和 `<!-- feishu-sync:end -->` 之间。
- 个人笔记应写在托管区域外；非 `feishu_*` Frontmatter 属性会保留。
- 修改托管区域会触发冲突保护，插件不会继续覆盖该文档。
- 文档首次分配的本地路径保持稳定，远端改名或移动不会破坏已有本地双链。

发生冲突后，在“同步中心 → 比较并处理”中选择：保留本地并暂停此文档；把本地正文保留到单独笔记区并应用远端；或备份后采用远端。应用远端前始终备份整篇本地笔记。预览后本地再次变化将停止操作。不要删除笔记来强制同步；本地笔记缺失时需要明确选择“恢复原路径笔记”或“关联已有笔记”。

## 推荐配置流程

1. 检查 `lark-cli` → 绑定自建应用 → 用户只读授权 → 再次检查用户身份。
2. 粘贴同步源链接，先预览数量和不支持的类型，再保存、设置目标目录并启用。新同步源默认关闭。
3. 选择“下载到本地”或“保留远端链接”；单文件默认上限 20 MB，可调整到 1–100 MB。
4. 手动同步一次，在同步中心检查结果后再开启自动同步。Obsidian 和插件需要保持运行。

界面跟随 Obsidian 的英文/简体中文设置。运行中的任务使用配置快照，修改配置从下一次开始生效。修改目标目录不搬移已有笔记；修改图片策略不批量改写已同步文档。未变化的定时任务不弹通知；连续失败会逐步延长下次间隔，最长 6 小时。

Obsidian 1.13 及以上支持设置分组搜索；1.11.4–1.12 保留兼容的旧版设置页。真实客户端和跨平台验收与自动化测试分开记录，见[发布检查清单](docs/release-checklist.md)。

## 升级、备份与恢复

已有的同步源、定时设置保持不变；新安装默认手动同步。更新后关闭再启用插件。首次加载会校验并迁移状态，保留 `data.pre-v1.json`；后续原子替换 `data.json`，并保留上一份 `data.backup.json`。每篇成功后保存进度。找到了笔记但没有对应基线时会进入冲突，不静默接管覆盖。

状态损坏或版本无法识别时，插件停止同步。在同步中心明确确认后才能恢复备份，现有文件保留为 `data.recovered-*.json`，恢复后关闭自动同步，供人工检查。没有可用备份时应保留文件并排查，不要清空状态强制接管。

冲突处理生成的完整笔记备份为插件目录下的 `note-backup-*.md`。状态、历史和备份可能包含私人文档元数据或正文；已加入 Git 忽略且不进入发布 ZIP，但仍可能被你的知识库同步/备份软件复制。插件不自动清理备份或未使用的图片。

## 同步源

目标同步源：

- 飞书 Wiki 指定空间或根节点
- 飞书云盘指定文件夹
- 单篇飞书或 Lark 文档

添加同步源时可以直接粘贴飞书或 Lark URL。插件会调用只读的 `drive +inspect` 自动识别资源类型、标题、Wiki 空间 ID 和内部 Token，无需用户手动查找这些技术字段。

## 开发环境

需要安装：

- Node.js 22.13 或更高版本（开发和 CI）
- npm
- Obsidian 1.11.4 或更高版本
- 飞书官方 `lark-cli`

安装依赖并启动开发构建：

```bash
npm install
npm run dev
```

执行类型检查、单元测试和生产构建：

```bash
npm run check
```

本地生成经过白名单校验的发布包：

```bash
npm ci --ignore-scripts
npm run package
```

产物是 `dist/feishu-lark-sync-1.0.1.zip` 和独立的 SHA-256 校验文件。ZIP 只包含九个白名单文件：`main.js`、`manifest.json`、`styles.css`、中英文 README、`LICENSE`、`CHANGELOG.md`、`PRIVACY.md`、`THIRD_PARTY_NOTICES.txt`。`dist/1.0.1/` 另提供可单独上传 Release 的文件和 `SHA256SUMS.txt`。依赖的完整许可证也嵌入 `main.js`，确保插件市场安装时仍然携带。打包不会遍历工作目录，不包含状态或笔记备份；不会发布到远端。CI 配置覆盖 Linux/macOS/Windows，正式发布前见[发布检查清单](docs/release-checklist.md)。

维护者在已有版本标签上手动运行 **Prepare release** 工作流：先通过三平台 CI，再校验标签、manifest 和工作流提交一致，为独立安装文件及 ZIP 生成 GitHub 构建来源证明。正式发布仍是独立、明确授权的步骤，必须使用该次工作流的原始产物。已发布版本不再替换附件或移动标签；修正应递增补丁版本。

本地测试时，将以下文件复制到 Obsidian Vault 的插件目录：

- `manifest.json`
- `main.js`
- `styles.css`

示例目录：

```text
<vault>/.obsidian/plugins/feishu-lark-sync/
```

然后在 Obsidian 的“设置 → 第三方插件”中启用 `Feishu Lark Sync`。

如果 `lark-cli` 通过 NVM 安装，建议在插件设置中填写 `command -v lark-cli` 返回的绝对路径。插件会把该可执行文件所在目录加入子进程 PATH，以便从 Finder 启动的 Obsidian 也能找到对应的 Node.js。

## 飞书应用和授权

插件采用 BYOA（用户自建应用）方式：

1. 用户在飞书开放平台创建自己的企业自建应用。
2. 为应用开通文档、云盘和知识库的必要读取权限。
3. 在插件设置中填写 App ID，并临时输入 App Secret 完成 `lark-cli` Profile 绑定。
4. 插件生成用户授权链接。
5. 用户在飞书或 Lark 中确认授权。
6. 后续同步通过用户身份访问该用户有权查看的资源。

飞书后台开通应用权限和用户授权是两层不同的权限，两者都满足后才能读取个人文档。

插件当前只申请以下三个只读 Scope：

- `wiki:wiki:readonly`
- `docx:document:readonly`
- `drive:drive:readonly`

插件不会申请知识空间成员管理、节点创建/移动、文档更新或删除等变更权限。

## 安全模型

- 每位用户使用自己的飞书/Lark 应用。
- App Secret 只在密码输入框中短暂存在，并通过 stdin 传递给 `lark-cli config init --app-secret-stdin`。
- 插件不会把 App Secret 或 Access Token 写入 Vault。
- 子进程调用使用 `child_process.spawn` 和 `shell: false`，不会拼接 Shell 命令。
- 文档操作均为只读，并明确使用用户身份；绑定应用、登录仅在用户操作时变更授权状态。
- 日志和诊断信息不得包含 Secret、Token、Device Code 或完整授权链接。
- 图片下载要求 HTTPS、可信飞书/Lark CDN 或用户明确添加的域名，并校验公开 IPv4、重定向、大小、超时和文件类型/签名；拒绝私网地址、HTML/JSON/SVG/XML 响应和不支持的格式。失败时保留远端链接并可重试。
- 下载文件采用不可变的 SHA-256 文件名，不覆盖旧图片。SVG、额外 CDN、仅 IPv6 的域名和少见附件格式可能只能保留远端链接。
- CLI 和下载可取消；卸载插件会中止进行中的任务。已提交的笔记保存进度，不回滚删除。

## 同步语义

- 飞书/Lark 是同步正文区域的数据源。
- 插件只更新 `feishu_*` 属性和受托管的正文区域。
- 托管区域之外的本地笔记和 Agent 生成内容永久保留。
- 根据 revision 或远端修改时间判断内容是否变化。
- 本地托管正文被修改后，不允许静默覆盖。
- 远端文档暂时不可见时，不立即视为删除。
- 远端消失不会默认删除本地文件。

详细模块设计和安全约束见[架构文档](docs/architecture.md)。

## 隐私和外部依赖

使用需要飞书/Lark 账号、自建应用和单独安装的官方 `lark-cli`；插件不会自动安装或更新 CLI。**CLI 会在知识库之外保存自己的配置、Profile 和凭据**，具体存储随平台与 CLI 版本变化，官方 CLI 使用系统原生凭据存储。“插件不保存密钥”不等于 CLI 不保存凭据。

CLI 会联系飞书/Lark API 和授权服务；图片附件下载联系可信 CDN 或明确添加的域名，显示远端图片也可能产生网络请求。插件没有遥测代码或维护者中转服务。配置的可执行程序拥有当前用户权限；状态、冲突备份、资源 URL 和笔记可能包含私人数据或带签名的媒体链接。停用/卸载不会删除笔记或撤销外部 CLI 的授权。完整说明见[隐私与数据处理](PRIVACY.md)。
